### 0.4 C1 僵尸模块检查结论

**零僵尸模块**。所有 79 个模块均被至少 1 个其他模块导入。导入图：

- **main.js**（入口）直接导入 42 个模块
- **settings.js** 导入 7 个设置子模块（settings-general / settings-advanced / settings-local-llm / perf-settings / rag-eval / memory-panel / trace-panel / durable-panel）
- **chat.js** 导入 4 个（context-bar / doc-mention / error-detail / feedback）
- **chat-render.js** 导入 4 个（empty-state / privacy-indicator / thinking-panel / skeleton）
- **keyboard.js** 导入 1 个（action）
- **markdown.js** 导入 1 个（wiki-links）
- **graph-viewer.js** 导入 1 个（graph-renderer）
- **sidebar.js** 导入 1 个（caret）

### 0.5 核心发现

1. **设置爆炸**：设置面板渲染 8+ 个子区域（S3 🔴 致命），其中 4 个为开发者工具不应暴露给普通用户
2. **Toggle 过多**：输入区 5 个 toggle（hybrid/agent/sub_agent/memory/web_search），用户无法理解 sub_agent 和 memory 的含义（S4 🔴）
3. **性能开关过度暴露**：perf-settings.js 12 个性能优化开关全部默认关闭（S8 🔴），用户永远不会去开
4. **开发者工具混入用户设置**：trace-panel / rag-eval / durable-panel / session-strip 四个模块是开发者工具但混在用户设置面板中（C3 🔴）
5. **借鉴功能场景模糊**：workflow-panel / code-executor / dream-panel 场景不明确（C3 🔴）
6. **大文件需拆分**：main.js(1604) / settings-advanced.js(1320) / security.js(1061) 三个文件过大（C4 🟠）
7. **工具库健康**：10 个工具库模块全部被使用，职责清晰（C1 ✅）
8. **核心 UI 健康**：chat.js / chat-render.js / markdown.js / sidebar.js 等核心模块职责清晰
