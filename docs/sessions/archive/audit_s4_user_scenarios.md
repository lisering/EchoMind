## 1. 用户画像定义

### 1.1 小明（新手用户）

| 维度 | 描述 |
|---|---|
| 背景 | 首次使用 RAG 工具，不了解技术概念（向量、嵌入、BM25） |
| 职业 | 学生 / 非技术从业者 |
| 技术水平 | 能熟练使用浏览器、Office，但不理解 API Key、Embedding 等概念 |
| 核心需求 | 导入文档 → 提问 → 获得答案，零配置 |
| 痛点假设 | 害怕「配错」，不理解设置面板中的任何技术术语 |
| 期望耗时 | 从安装到获得第一个回答 ≤ 2 分钟 |

### 1.2 小王（知识工作者）

| 维度 | 描述 |
|---|---|
| 背景 | 研究员 / 研究生 / 律师 / 咨询师，定期处理大量文档 |
| 职业 | 需要精确引用来源、管理分类、导出成果 |
| 技术水平 | 理解 API Key 配置，会使用文献管理工具（Zotero/EndNote） |
| 核心需求 | 批量管理、精确搜索、导出引用、多知识库分离 |
| 痛点假设 | 检索结果不够精确时会困惑，需要手动调参 |
| 期望耗时 | 导入 50 篇文档 ≤ 5 分钟，精确搜索 ≤ 3 秒 |

### 1.3 小李（高级用户）

| 维度 | 描述 |
|---|---|
| 背景 | 开发者 / 技术爱好者，需要精细控制 RAG 管线 |
| 职业 | 全栈工程师 / AI 研究员 |
| 技术水平 | 理解 RAG 架构、Embedding 模型选择、采样参数调优 |
| 核心需求 | 自定义模型、调参、本地 LLM、API 集成、文件监听 |

## 12. 审计结论

### 12.1 核心结论

EchoMind 的功能矩阵**完全覆盖**三类用户的核心场景（15/15 = 100%），但当前 UI 的**暴露过度**导致 3 个场景有卡点。S3 提出的三大重整方案（智能模式 + 8 分区 + 2 toggle）经 S4 验证全部可行，能将场景流畅度从 80% 提升至 100%。

### 12.2 三大方案验证结果

| 方案 | 验证结果 | 改善效果 | 状态 |
|---|---|---|---|
| 智能模式 | 93.3% 场景无需手动配置 | 检索质量从「基础」→「最佳」 | ✅ 通过 |
| 8 分区 | 每项 1 次点击可达 | 设置查找时间 -80%~97% | ✅ 通过 |
| 2 toggle | 5/5 场景覆盖 | 认知负荷 -60% | ✅ 通过 |

### 12.3 S3 方案修正建议（N3/N6/N7）

| 修正项 | S3 原方案 | S4 修正建议 | 理由 |
|---|---|---|---|
| PagedAttention/GEMV/KV Cache | 归入「模型配置」子项 | 移入隐藏「开发者菜单」 | 推理引擎内部参数，高级用户也很少调整 |
| VLM 图片理解 | 归入「智能检索」分区 | 移入「模型配置」分区 | VLM 是 BYOK Pro 功能，与智能模式逻辑不同 |
| 高级调优分区内容 | 含 PagedAttention/GEMV/KV Cache | 排除以上，仅保留 Token/采样/压缩/实验性 | 分区聚焦用户可理解的调优参数 |

### 12.4 预期效果

| 指标 | 当前 | 重整后 | 改善 |
|---|---|---|---|
| 场景覆盖率 | 100% | 100% | 不变 |
| 场景流畅度 | 80% (12/15) | 100% (15/15) | +20% |
| 智能模式覆盖 | 0% | 93.3% | +93.3% |
