## 1. 框架概述

### 1.1 设计原则
| 原则 | 说明 |
|------|------|
| **数据驱动** | 所有决策基于量化数据 + 定性洞察 |
| **闭环管理** | 反馈 → 分析 → 行动 → 验证 → 反馈 |
| **分层处理** | P0 即时响应 / P1 周内响应 / P2 迭代规划 |
| **用户分层** | 重度/轻度/演示模式/流失风险 分层运营 |

### 1.2 核心指标体系

| 维度 | 核心指标 | 目标值 | 采集频次 |
|------|----------|--------|----------|
| **激活留存** | 周活跃率 (WAU/MAU) | ≥ 60% | 周 |
| | 次日留存 | ≥ 40% | 日 |
| | 7日留存 | ≥ 30% | 周 |
| **使用深度** | 人均周对话轮数 | ≥ 10 | 周 |
| | 人均导入文档数 | ≥ 5 | 周 |
| | 核心功能覆盖率 | ≥ 80% | 周 |
| **体验质量** | NPS | ≥ 30 | 周 |
| | 任务完成率 | ≥ 95% | 周 |
| | 平均任务耗时 | 核心任务 < 2min | 周 |
| **稳定性** | 崩溃率 | < 0.1% | 日 |
| | ANR/卡顿率 | < 1% | 日 |
| | P0 Bug 清零率 | 100% | 日 |

## 2. 数据采集体系

### 2.1 自动化埋点（客户端 SDK）

```json
{
  "event": "chat_completed",
  "timestamp": "2026-09-06T10:30:00Z",
  "user_id": "hashed_user_id",
  "session_id": "uuid",
  "properties": {
    "conversation_id": "uuid",
    "duration_ms": 12500,
    "token_usage": {"prompt": 1200, "completion": 800, "total": 2000},
    "retrieval_mode": "hybrid",
    "rerank_enabled": true,
    "hyde_enabled": false,
    "sources_count": 5,
    "degraded": false,
    "error": null,
    "model": "gpt-4o-mini",
    "embedding_model": "bge-small-en-v1.5"
  }
}
```

**核心事件清单**：

| 事件名 | 触发时机 | 关键属性 |
|--------|----------|----------|
| `app_start` | 应用启动 | version, os, arch, cold_start_ms |
| `config_completed` | 向导完成 | has_api_key, model, time_to_complete |
| `document_imported` | 导入完成 | file_type, size_mb, chunk_count, duration_ms, success |
| `chat_started` | 发送消息 | conversation_id, query_length, retrieval_mode |
| `chat_completed` | 收到完整回答 | duration_ms, token_usage, sources_count, degraded |
| `chat_error` | 发生错误 | error_code, error_type, recoverable |
| `settings_changed` | 保存设置 | key, old_value, new_value |
| `export_completed` | 导出完成 | format, size_kb, duration_ms |
| `budget_exceeded` | 预算超限 | current_spend, limit, action_taken |
| `crash` | 应用崩溃 | stack_trace, context, user_action |

## 3. 分析方法论

### 3.1 定量分析框架

#### A. 用户分群分析（RFM 模型改良）

| 维度 | 指标 | 分层标准 |
|------|------|----------|
| **Recency (近度)** | 最后活跃天数 | 活跃(≤3天) / 沉默(4-14天) / 流失(>14天) |
| **Frequency (频次)** | 周活跃天数 | 高频(≥4) / 中频(2-3) / 低频(1) / 零频(0) |
| **Monetary (价值)** | 累计对话轮数/文档数 | 高价值(≥50轮) / 中(10-49) / 低(<10) |

**分群矩阵**：

| 分群 | 策略 |
|------|------|
| **冠军用户** (高R、高F、高M) | 共创设计、优先体验、终身Pro |
| **忠诚用户** (高R、高F、中M) | 深度访谈、共创设计、优先支持 |
| **潜力用户** (高R、中F、低M) | 引导深度使用、功能教育、视频教程 |
| **新用户** (高R、低F、低M) | 引导上手、核心流程体验、快速上手指南 |
| **流失风险** (低R、任意F、任意M) | 唤醒邮件、专属优化、专人电话 |
| **流失用户** (极低R、极低F) | 最后挽留、痛点诊断、延长免费期 |

#### B. 漏斗分析

```
启动应用 (100%)
    ↓ 85%
完成配置向导
    ↓ 70%
导入首个文档
    ↓ 60%
完成首次问答
    ↓ 45%
第2周仍活跃
    ↓ 30%
第4周仍活跃 (留存)
```

**关键流失节点**：配置向导完成→首次导入 (流失 15%)、首次导入→首次问答 (流失 10%)

#### C. 功能使用热力图

| 功能 | 使用人数占比 | 使用频次/人/周 | 满意度 | 优先级 |
|------|--------------|----------------|--------|--------|
| 文档导入 | 95% | 3.2 | 4.2/5 | 维护 |
| 基础聊天 | 98% | 12.5 | 4.5/5 | 优化 |
| 混合检索 | 45% | 2.1 | 3.8/5 | 推广 |
| 重排序 | 28% | 1.2 | 3.5/5 | 优化/教育 |
| 演示模式 | 35% | 1.0 | 4.0/5 | 完善 |
| 导出导出 | 40% | 0.8 | 4.1/5 | 维护 |
| 预算管理 | 15% | 0.3 | 3.2/5 | 简化 |
| 导出导入 | 20% | 0.5 | 3.9/5 | 完善 |

### 3.2 定性分析框架

#### A. 主题建模 (Topic Modeling)

使用 LDA/LLM 对开放式反馈自动聚类：

| 主题簇 | 关键词 | 占比 | 代表性引述 | 行动建议 |
|--------|--------|------|------------|----------|
| **导入体验** | 导入、速度、格式、失败、进度 | 28% | "导入 100MB PDF 卡在 99% 很久" | 优化大文件分块、增加断点续传 |
| **检索质量** | 准确、相关、幻觉、引用、遗漏 | 22% | "经常引用不相关的段落" | 调整 score_threshold、优化 chunk 大小 |
| **回答质量** | 幻觉、逻辑、完整、推理、语气 | 18% | "回答前言不搭后语" | 增加 reasoning_content 支持、优化 system prompt |
| **性能速度** | 慢、卡顿、等待、超时、内存 | 15% | "首次聊天等了 20 秒" | 优化 ONNX 预热、增加预加载 |
| **易用性** | 界面、直观、设置、快捷键、导出 | 12% | "设置项太多不知道改哪个" | 简化设置分组、增加搜索 |

#### B. 情感分析

使用情感分类器对每条反馈打标：

| 情感 | 占比 | 典型表达 | 处理优先级 |
|------|------|----------|------------|
| **极度不满** | 3% | "完全不可用"、"数据丢失"、"崩溃" | P0 即时 |
| **不满** | 12% | "太慢"、"不好用"、"Bug 多" | P1 周内 |
| **中性** | 35% | "一般"、"还可以"、"凑合" | P2 迭代 |
| **满意** | 38% | "好用"、"不错"、"推荐" | 维护 |
| **极度满意** | 10% | "惊艳"、"超预期"、"完美替代" | 复制推广 |

## 4. 反馈处理流程 (SOP)

### 4.1 分级响应标准

| 级别 | 定义 | 响应时效 | 处理流程 | 责任人 |
|------|------|----------|----------|--------|
| **P0 致命** | 崩溃、数据丢失、安全漏洞、核心功能不可用 | 1 小时确认，4 小时修复发布 | 1. 确认复现 → 2. 热修复 → 2. 发布热修复版 → 4. 通知用户 | 核心开发 + QA |
| **P1 严重** | 核心功能异常、性能严重退化、数据不一致 | 4 小时确认，24 小时修复 | 1. 确认复现 → 2. 根因分析 → 3. 修复验证 → 4. 发布 | 核心开发 |
| **P1 体验** | 核心流程卡顿、关键错误提示不清 | 24 小时确认，1 周修复 | 1. 复现 → 2. 设计修复 → 3. 代码评审 → 4. 合并 | 对应模块 Owner |
| **P2 一般** | 非核心功能 Bug、UI 细节、文档错误 | 1 周确认，下个迭代修复 | 正常敏捷流程 | 对应模块 Owner |
| **P3 建议** | 功能建议、UI 优化、文档完善 | 记录入池、季度规划 | 产品规划会评估 | PM |

### 6.2 自动化流水线

```yaml

  - extract: 从 ClickHouse 抽取昨日原始事件

  - extract: 抽取周度聚合数据

  - report: 生成周度报告 PDF + HTML
  - distribute: 邮件分发 + 发布到 Confluence

# 每月 1 号 10:00 UTC 运行
monthly_pipeline:
  - cohort: 留存队列分析
  - churn: 流失预测模型推理
  - nps: NPS 趋势分解
  - report: 月度战略报告
```

## 7. 数据治理与合规

### 7.1 隐私保护

| 原则 | 实施 |
|------|------|
| **最小化采集** | 仅采集产品改进必需字段，不采集 PII |
| **本地优先** | 埋点数据本地加密缓存，批量上传 |
| **匿名化** | 用户 ID 哈希化，IP 地址脱敏 |
| **用户控制** | 设置中可随时关闭遥测、查看/导出/删除数据 |
| **保留期限** | 原始事件 90 天，聚合指标永久保留 |

### 7.2 数据安全

| 措施 | 实施 |
|------|------|
| **传输加密** | TLS 1.3 端到端加密 |
| **存储加密** | 静态数据 AES-256 加密 |
| **访问控制** | RBAC 权限模型，最小权限原则 |
| **审计日志** | 所有数据访问操作记录审计 |
| **合规认证** | 按 GDPR/CCPA/个人信息保护法 合规设计 |

## 8. 附录

### 附录 A：常用 SQL 查询模板

```sql
-- 周活跃用户数
SELECT count(DISTINCT user_id) as wau
FROM events
WHERE event_time >= now() - interval '7 days'
  AND event_name = 'app_start';

-- 功能使用热力图
SELECT event_name, count(DISTINCT user_id) as users, count(*) as total_events
FROM events
WHERE event_time >= now() - interval '7 days'
GROUP BY event_name
ORDER BY users DESC;

-- 用户分群分布
SELECT 
  CASE 
    WHEN last_active_days <= 3 AND weekly_active_days >= 4 AND total_chats >= 50 THEN '冠军'
    WHEN last_active_days <= 3 AND weekly_active_days >= 2 AND total_chats >= 10 THEN '忠诚'
    WHEN last_active_days <= 3 THEN '潜力'
    WHEN last_active_days <= 14 THEN '流失风险'
    ELSE '流失'
  END as segment,
  count(*) as user_count
FROM user_summary
GROUP BY segment;

-- NPS 计算
SELECT 
  (count(*) FILTER (WHERE nps_score >= 9) - count(*) FILTER (WHERE nps_score <= 6)) * 100.0 / count(*) as nps
FROM survey_responses
WHERE submitted_at >= now() - interval '7 days';
```
