## 二、分维度详评

### 1. 架构设计 — 9.0 ✅ 优势显著

```
models(4189行) ← core(56315) ← tauri-app(16845)
        prompt(1667) / compact(3200) / context(1776) 支撑层
        infra(36543) 适配器层 ＋ license-issuer(467) CLI
```

- **分层纪律真实有效**：`tauri-app → core → models` 依赖方向经审查强制，core 不 import infra——这在 AI 辅助开发盛行的当下极为难得
- Port-Trait 抽象到位（Loader/Splitter/Embedder/Storage/LLMProvider/Reranker），Pro 门控走 `#[cfg]` 条件编译符合 OCP
- **扣分点**：前端 `main.js`(1924行·7职责)、`chat.js`(1061行·339行事件处理器) 两个上帝模块待拆（P4-3/P4-4 已立项）；chat-render⇄chat 循环依赖已在 V3.1 解除

### 2. 代码质量 — 8.5 ✅ 纪律性强

- workspace 级 deny lint（unwrap/expect/panic/todo/unreachable）+ clippy `-D warnings` 双保险，实测零警告
- TODO/FIXME 全仓仅 2 处且为 phase4 合法占位；零孤儿模块、零僵尸 CSS
- `unsafe` 仅 20 处，集中于量化 GEMV 内核/GGUF 流式读取/磁盘查询等合理场景（有安全论证要求约束）
- **扣分点**：前端 30,736 行中 36% 集中在 9 个超 800 行模块；`t() || '中文'` 双写回退模式 163 处易漂移

### 3. 测试体系 — 9.5 ✅ 项目最大亮点之一

| 层 | 规模 | 实测状态 |
|---|---|---|
| Rust 单元/集成 | 2007 个测试函数 | Free 1699 passed, 0 failed |
| Vitest 前端单测 | 1826 用例 / 93 文件 | 全绿 |
| Playwright E2E | 117 spec / 1566 passed | 15 分钟全量零失败 |
| 混沌测试 | 7 类野蛮语料（XSS/混合编码/格式欺骗/深嵌套） | CI `--include-ignored` |
| 真实 LLM E2E | 环境变量门控 | ⚠️ CI 永不执行（见风险 R2） |

TDD + Spec-driven 双铁律驱动，测试名可追溯到 REQ/TC 编号。**V3.1 关键改进**：清除了 28 个死 mock——"mock 与真实后端偏差掩盖回归"（历史上 11 个幻影调用逃过测试的根因）的土壤已铲除。

### 4. 性能 — 8.5 ✅ 后端优于前端

- **后端优秀**：38 个 SQLite 索引全覆盖、HNSW 阈值自动切换（500 向量，量化论证完整）、Arc 快照零深拷贝、`select_nth_unstable_by` O(N) top-k、嵌入批处理 64/批 + 单事务写入、语义缓存金字塔默认开启
- **V3.1 已消除的前端热点**：hljs 每帧重高亮（O(n²)→豁免）、IPC 风暴（200次→合流）、boot 串行 IPC（并行×4）、会话列表全量渲染（50/批）
- **剩余**：长会话打开仍全量串行渲染（P4-5 方案已定型）；导入文件间无流水线重叠（预估损失 20-40% 吞吐）；perf.rs 生产埋点刚接入，观测闭环待积累数据

### 5. 安全 — 9.0 ✅ 行业前沿水准

- 静态：SQLCipher AES-256 + Argon2id KDF + PII 8类脱敏入管线 + 哈希链审计日志 + 暴力破解退避 + 恐慌抹除
- LLM 应用安全：Prompt 注入三层防御、不可见字符清除、PII 送模型前脱敏——明确对标 OWASP GenAI LLM Top 10 2026（含新增的 LLM09 向量嵌入弱点条款）
- 商业防护：付费墙在后端 `import_one` 内强制拦截（REQ-LIC-002 双重防御），API Key 永不回传前端
- **关注点**：20 处 unsafe 需按铁律保持 Miri 覆盖；`data-i18n-html` 直接 innerHTML 插翻译文本是潜在 XSS 面（语言包受信前提下可控）

### 6. 文档治理 — 9.0 ✅ 纪律即竞争力

- SRS（REQ 编号 + AC + TC 全追溯）+ SOFTWARE_ASSET 全量索引 + 16 篇 ADR + api/ 四件套契约文档 = 250 个文档
- Session 自动管理（CURRENT_STATE 快照 → LOG → NEXT_SESSION 提示词）跨会话上下文零丢失
- "一个事实一个归属"原则执行良好（AGENTS.md 只留入口指引不重复资产清单）
- **扣分点**：250 个文档中含大量历史 NEXT_SESSION 归档，检索噪音渐增；CLAUDE.md 与 AGENTS.md 存在内容重叠需人工保持一致

### 7. 产品完成度 — 9.5

功能矩阵 P0-P2 全部 Done（导入 9 格式 / 检索全家桶 / 多模态 Pro / 本地 GGUF / MCP Phase 1）。三轮复盘 6 个 P0 已关闭 5 个。UX 审计四轮（S1-S4）的 P0 全部消化（设置 35→8 分区、toggle 5→2、开发者工具归菜单）。

### 8. 工程流程 — 8.5

CI 流水线完整（lint ∥ frontend ∥ supply-chain → test → build-matrix 4OS×2 → e2e 分片 → release-build），pre-commit 秘密扫描，双仓库发布同步脚本。**扣分点**：当前工作区累积大量未提交变更（git 卫生风险）；全量 E2E 15 分钟对迭代节奏偏重。

## 四、结论

这个项目最稀缺的不是功能广度（那已经足够多），而是**把纪律变成了可执行的基础设施**：deny lint 让"零 panic"不是口号而是编译失败，SPEC→TC→实现链条让每个功能可追溯，Session 管理让 AI 协作的上下文不丢失。V3.1 之后，历史上最危险的"mock 掩盖回归"问题已被系统性清除。

**下一步建议**（按序）：① 提交当前工作区变更固化成果 → ② 完成 P4 四项重构 → ③ 给 real-data.spec 加可选 CI job 关闭 R2 → ④ 评估 v3.1.0 发版。
