## Phase 2: Top 5 功能技术调研

### 2.1 功能 1：.docx 文档导入

#### 用户场景

律师、研究人员、咨询顾问等知识工作者大量使用 Microsoft Word 撰写合同、论文、报告。当前 EchoMind 仅支持 `.md`/`.txt`/`.pdf`，无法导入 Word 文档——这是用户反馈最多的格式缺口。

#### 技术方案

**推荐方案**：使用 `docx-rs` crate（纯 Rust .docx 解析）

- 读取 .docx ZIP 包（Office Open XML 格式）
- 解析 `word/document.xml`（段落、表格、标题层级）
- 提取纯文本 + 段落边界（双换行，与 MarkdownLoader 一致）
- 表格转换为 Markdown 表格语法
- 图片提取为 alt 文本标注（`[图片]`），不提取二进制内容

**备选方案**：`mammoth` Rust 移植（HTML 中间格式），但增加一层转换开销。

#### 依赖

| 依赖 | 版本 | 用途 | 来源 |
|---|---|---|---|
| `docx-rs` | `0.4.22` | .docx 文件读取与解析 | `cargo search docx-rs`（2026-08-06 确认最新） |

> **铁律六**：`cargo search docx-rs` 确认最新版本为 `0.4.22`（非任务描述中的 `0.1`）。

#### 改动文件

|---|---|---|

| `crates/core/src/loader.rs` | 新增 struct | `DocxLoader` 实现 `Loader` trait |
| `crates/core/src/loader_tests.rs` | 新增测试 | TC-ING-DOCX-001~004 |
| `crates/core/src/import.rs` | 修改常量 | `ALLOWED_EXTENSIONS` 新增 `"docx"` |
| `crates/core/src/import.rs` | 修改逻辑 | `import_one()` 中 `.docx` 走 `DocxLoader` |
| `ui/locales/en.json` | 新增 i18n | `docx` 文件类型标签 |
| `ui/locales/zh-CN.json` | 新增 i18n | `docx` 文件类型标签 |

#### DocxLoader 实现规格

```rust
/// .docx 文档加载器（REQ-ING-015）：基于 docx-rs 解析 Office Open XML。
/// 提取段落文本 + 表格（转 Markdown 表格）+ 标题层级。
/// 图片以 [图片] alt 文本替代，不提取二进制内容。
pub struct DocxLoader;

impl DocxLoader {
    fn extract(file_path: &str) -> anyhow::Result<String> {
        // 1. docx-rs 读取 .docx 文件
        // 2. 遍历文档 body 的 child elements
        // 3. Paragraph → 提取文本，双换行分隔
        // 4. Table → 转 Markdown 表格语法
        // 5. Heading → 保留层级信息（# ## ###）
        // 6. Image → [图片] 占位符
    }
}

impl Loader for DocxLoader {
    async fn load(&self, file_path: &str) -> anyhow::Result<String> {
        let owned = file_path.to_string();
        tokio::task::spawn_blocking(move || Self::extract(&owned))
            .await
            .context("DocxLoader 解析任务执行失败")
    }
}
```

### 2.2 功能 2：.html 文档导入

#### 用户场景

用户从网页保存 HTML 文件（技术文档、博客文章、API 文档），希望导入知识库进行 RAG 检索。也可作为未来浏览器剪藏功能的前置能力。

#### 技术方案

**推荐方案**：使用 `html2text` crate（纯 Rust HTML → 纯文本）

- 解析 HTML DOM
- 提取正文内容（去除 `<nav>`/`<header>`/`<footer>`/`<script>`/`<style>`）
- 保留标题层级（`<h1>`~`<h6>` → `#`~`######`）
- 保留链接文本（丢弃 URL，保留 anchor text）
- 保留列表结构（`<ul>`/`<ol>` → Markdown 列表）

**备选方案**：`scraper` + 手动 DOM 遍历，但 `html2text` 已封装好 HTML→Markdown 转换。

#### 依赖

| 依赖 | 版本 | 用途 | 来源 |
|---|---|---|---|
| `html2text` | `0.17.1` | HTML → 纯文本/Markdown 转换 | `cargo search html2text`（2026-08-06 确认最新） |

> **铁律六**：`cargo search html2text` 确认最新版本为 `0.17.1`（非任务描述中的 `0.13`）。

#### HtmlLoader 实现规格

```rust
/// .html 文档加载器（REQ-ING-016）：基于 html2text 解析 HTML。
/// 提取正文内容，保留标题层级和列表结构，去除导航/脚本/样式。
pub struct HtmlLoader;

impl HtmlLoader {
    fn extract(file_path: &str) -> anyhow::Result<String> {
        // 1. 读取 HTML 文件（from_utf8_lossy 容错编码）
        // 2. html2text 配置：保留标题层级 + 列表 + 链接文本
        // 3. 后处理：压缩连续空行、修剪首尾空白

}

impl Loader for HtmlLoader {
```

### 2.3 功能 3：浅色主题切换

#### 用户场景

白天办公环境下暗色主题对比度过高，部分用户强烈要求浅色主题。当前 `tokens.css` 已定义完整的 CSS 变量体系（暗色主题），浅色主题只需新增变量集 + 切换逻辑。

#### 技术方案

**推荐方案**：CSS 变量 + `data-theme` 属性 + `localStorage` 持久化

- `tokens.css` 新增 `[data-theme="light"]` 变量集（全部覆盖暗色变量）
- `main.js` 新增 `setTheme(theme)` 函数 + `localStorage` 持久化
- `settings.js` 新增主题切换 UI（toggle 按钮或下拉选择）
- 设置面板新增「外观」区域
- 后端持久化到 settings 表（`ui.theme` 键）

**备选方案**：Tailwind `dark:` 前缀全量迁移——工作量大（49 个 JS 文件），不推荐。

**关键设计**：利用已有 CSS 变量体系。`tokens.css` 中所有颜色通过 CSS 变量引用（`var(--surface-0)` 等），Tailwind config 映射到这些变量。浅色主题只需覆盖变量值，无需修改任何组件代码。

#### 依赖

无新增依赖（纯 CSS + JS）。

#### 改动文件

|---|---|---|
| `ui/styles/tokens.css` | 新增变量集 | `[data-theme="light"]` 全部颜色变量覆盖 |
| `ui/src/main.js` | 新增函数 | `setTheme(theme)` + `getTheme()` + `localStorage` |
| `ui/src/settings.js` | 新增 UI | 主题切换区域（暗色/浅色/跟随系统） |
| `ui/locales/en.json` | 新增 i18n | 主题相关文案 |

| `e2e-tests/tests/bridge/tauri-stub.js` | 新增 mock | `set_theme` / `get_theme` |

### 2.4 功能 4：语音输入 + TTS 朗读

#### 用户场景

- **语音输入**：用户通过麦克风语音提问，实时转写填入聊天输入框（免打字交互）
- **TTS 朗读**：用户点击「朗读」按钮，助手回答通过语音合成播放（眼睛疲劳时听答案）

#### 技术方案

**推荐方案**：Web Speech API（浏览器原生，零依赖）

**语音输入**：
- `window.SpeechRecognition` / `window.webkitSpeechRecognition`
- 麦克风权限请求（Tauri `dialog` 插件或 `webkit` 原生）
- 实时转写 → 填充到 `#inputBar`
- 支持中英文（`lang = 'zh-CN'` 或 `'en-US'`）
- 语言跟随当前 UI 语言

**TTS 朗读**：
- `window.speechSynthesis`
- 朗读助手回答（从 `chat_done` 事件后的 `.ai-message` 元素提取纯文本）
- 语速/音色可配置（设置面板）
- 朗读进度高亮（可选，v1.2 候选）

**备选方案**：Whisper.cpp 本地语音识别（Pro 门控）——精度更高但依赖重，列为 v1.2 候选。

#### 依赖

无新增 Rust/npm 依赖（Web Speech API 是浏览器原生 API）。

> **关键验证点**：Tauri WebView（macOS WKWebView / Windows WebView2 / Linux WebKitGTK）对 Web Speech API 的支持度需在 S47 开始时验证。若不支持，降级为「功能不可用」并隐藏 UI 入口。

### 2.5 功能 5：网页搜索集成

#### 用户场景

用户提出问题后，RAG 检索本地知识库。若本地知识库无相关内容或信息不足，自动（或用户手动触发）搜索互联网，将搜索结果摘要作为 RAG context 补充，实现「本地知识 + 互联网」混合检索。

#### 技术方案

**推荐方案**：DuckDuckGo Instant Answer API + 可选 SearXNG 自托管

**DuckDuckGo Instant Answer API**（零依赖，HTTPS GET）：
- API 端点：`https://api.duckduckgo.com/?q={query}&format=json&no_html=1`
- 返回 Instant Answer 摘要 + 相关主题
- 无需 API Key，无速率限制（合理使用）
- 适合快速事实查询

**SearXNG 自托管**（可选，Pro 门控）：
- 用户自部署 SearXNG 实例（Docker 一键部署）
- 配置 SearXNG URL 到 settings（`search.searxng_url`）
- 更丰富的搜索结果（标题 + 摘要 + URL）

**集成方式**：
- 新增 `WebSearchProvider` trait（core 层）
- `DuckDuckGoProvider` 实现（infra 层，使用已有 `reqwest`）
- `chat_inner` 中检测 `rag.web_search_enabled` 设置
- 检索结果不足时（`sources.is_empty()` 或分数 < 阈值）自动触发搜索
- 搜索结果作为补充 context 注入 RAG prompt
- 搜索结果标注 `[网络搜索]` 前缀，与本地知识库来源区分

**安全考量**：
- 网络搜索是 **opt-in** 功能（默认关闭）
- 搜索查询仅发送到搜索引擎，不经过第三方 LLM
- 搜索结果作为 RAG context 补充，不替代本地知识库
- 用户可在设置中配置搜索引擎（DuckDuckGo / SearXNG）
- 搜索结果 URL 和摘要存储在对话上下文中，不持久化到数据库

无新增 Rust 依赖（复用已有 `reqwest`）。

#### WebSearchProvider trait 设计

```rust
/// 网页搜索提供商端口（REQ-RAG-036）。
/// 搜索查询 → 搜索结果列表（标题 + 摘要 + URL）。
/// 对象安全：使用 `Pin<Box<Future>>` 返回类型。
pub trait WebSearchProvider: Send + Sync {
    /// 执行搜索，返回 top-k 结果。
    fn search(
        &self,
        query: &str,
        max_results: usize,
    ) -> Pin<Box<dyn Future<Output = anyhow::Result<Vec<SearchResult>>> + Send + '_>>;
}

/// 搜索结果。
#[derive(Debug, Clone, serde::Serialize)]
pub struct SearchResult {
    pub title: String,
    pub snippet: String,
    pub url: String,
    pub source: String,  // "DuckDuckGo" / "SearXNG"
}
```

#### 风险

| 风险 | 级别 | 缓解措施 |
|---|---|---|
| DuckDuckGo API 速率限制 | 中 | 实现客户端节流（max 1 req / 3s），缓存搜索结果 |
| 搜索结果质量不稳定 | 中 | 仅取 Instant Answer（高质量），忽略 Related Topics 列表 |
| 网络不可用时功能失效 | 低 | 优雅降级，仅用本地知识库 |
| 隐私：查询发送到搜索引擎 | 中 | opt-in + 用户明确知晓（设置面板警告文案） |
| SearXNG 自部署门槛 | 低 | Pro 门控，文档提供 Docker 部署指南 |
