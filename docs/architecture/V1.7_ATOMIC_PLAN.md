## 3. v1.7 选定功能

### 3.1 F1: Q06/S71 Shadow Screen 集成（P0，ROI 7.3）

**背景**：`SecurityManager` 的 `SecurityPosture` 支持 Strict 模式，`ShadowScreenCollector` 已收集统计，
但 `run_shadow_screen()` / `llm_classify()` 从未在生产代码调用。安全 Strict 模式下应有 Shadow 筛查。

**目标**：在 `chat_inner` 中，当 `security_posture == Strict` 时，对用户输入执行 LLM 安全分类，
并与权威决策对比，记录 Agreement/Disagreement 统计。

**实现规格**：

```
输入：用户 query + security_posture
输出：SecurityScreenVerdict (Allow/Deny/Unscreened) + ShadowScreenStats 更新
边界：LLM 不可用时降级为 Unscreened（不影响对话流）
错误处理：Shadow 筛查超时 5s → 降级为 Unscreened
```

**实现步骤**：
1. S1: `chat_inner` 中 `security_posture == Strict` 时调用 `llm_classify()` 获取 Shadow 裁决
2. S2: `run_shadow_screen()` 并行执行权威 + Shadow 筛查
3. S3: 前端 `security-advanced-features.spec.ts` E2E 验证

**TDD 测试**：
- TC-SHADOW-INTEGRATE-001: Strict 模式下 Shadow 筛查被触发
- TC-SHADOW-INTEGRATE-002: LLM 不可用时降级为 Unscreened
- TC-SHADOW-INTEGRATE-003: Shadow 不影响权威决策（安全隔离）

### 3.2 F2: B06 SessionCoordinator 集成（P1，ROI 5.9）

**背景**：`SessionCoordinator` 在 `state.rs` 中初始化，但 `.run()` 从未被 `chat_inner` 调用。
当前 `chat_inner` 直接调用 `ChatEngine`/`AgentEngine`/`CoordinatorEngine`。

**目标**：用 `session_coordinator.run()` 包装对话执行，实现会话级任务编排（串行化/中断/唤醒）。

**实现步骤**：
1. S2: `chat_inner` 中用 `session_coordinator.run(conv_id, || async { ... })` 包装对话执行
2. S3: 验证 `interrupt()` 和 `wake()` 在 abort_chat 场景下正确工作

**TDD 测试**：
- TC-COORD-INTEGRATE-001: 会话级串行执行（同会话不并发）
- TC-COORD-INTEGRATE-002: interrupt 中断后清理
- TC-COORD-INTEGRATE-003: wake 合并唤醒

### 3.3 F3: 向量缓存 LRU 驱逐（P1，ROI 5.7）

**背景**：`SqliteStorage` 的 `vector_cache` 字段全量加载到内存，无 LRU 驱逐。
大规模知识库（10K+ chunks）时内存占用高。

**目标**：为 `vector_cache` 添加 LRU 驱逐策略，当向量数超过阈值时保留最近访问的 N 个。

**实现步骤**：
1. S4: `SqliteStorage::vector_cache` 改为 `Arc<RwLock<LruCache<String, Vec<f32>>>>`
2. S5: 添加 `max_vectors` 配置项（默认 5000），超限时驱逐最久未访问

**TDD 测试**：
- TC-LRU-001: 缓存满时驱逐最旧条目
- TC-LRU-002: 检索操作更新访问顺序
- TC-LRU-003: 写操作失效对应条目

### 3.4 F4: 启动并行化（P1，ROI 5.3）

**背景**：当前启动时 `AppState` 初始化串行执行（storage → embedder → settings）。
`cargo tauri dev` 冷启动 ~3s，可优化。

**目标**：并行化独立初始化路径（settings 读取 + embedder 预热 + 安全状态恢复）。

**实现步骤**：
1. S6: `AppState::new()` 中 `tokio::join!` 并行化独立初始化
2. S7: 添加启动耗时 tracing span

**TDD 测试**：
- TC-BOOT-001: 并行初始化结果一致
- TC-BOOT-002: 单项初始化失败不影响其他项
