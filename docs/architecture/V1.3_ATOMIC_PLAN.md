### 1.3 评分依据

#### 本地知识图谱导出（ROI 15.0）
- **用户需求度 3**：知识图谱可视化已实现（D3 force-directed graph），用户希望将图谱数据导出为标准格式（GraphML/JSON-LD），用于外部工具分析（Gephi、Neo4j、Cytoscape）或备份。
- **技术可行性 5**：`entity_relations` 表 + `entities` 表已有完整图数据。GraphML 是 XML 格式，可用字符串拼接生成（无需 quick-xml）；JSON-LD 是 JSON 格式，`serde_json` 已是依赖。`list_all_relations()` + `list_all_entities()` Storage 方法已存在。
- **预计天数 1**：2 个导出函数 + 2 个 IPC 命令 + 前端导出按钮 + 测试 + 文档。

#### 文档摘要自动生成（ROI 13.3）
- **用户需求度 4**：用户导入大量文档后，需要快速了解每篇文档的核心内容。当前仅显示文件名和状态，缺乏内容概览。自动摘要是知识管理工具的高频需求。
- **技术可行性 5**：`LLMProvider` trait 已有 `chat_stream()` 方法，可复用非流式调用生成摘要。`ImportService` 导入管线已完善，在嵌入完成后追加摘要生成步骤即可。`Document` 结构体新增 `summary` 字段。
- **预计天数 1.5**：Document 模型扩展 + 摘要生成逻辑 + 前端摘要展示 + 测试 + 文档。

#### 对话模板/快捷指令系统（ROI 13.3）
- **用户需求度 4**：现有 `slash-commands.js` 已有 6 个硬编码快捷指令（summary/compare/extract/translate/timeline/mindmap），用户希望自定义模板（如法律分析、代码审查、论文摘要等场景化 prompt 模板）。
- **技术可行性 5**：模板存储复用 settings 表 JSON 序列化模式（与 workflow 模板一致）。前端在现有 slash-commands.js 基础上扩展自定义模板加载。零新增依赖。
- **预计天数 1.5**：后端 CRUD + 前端模板管理 UI + slash-commands 集成 + 测试 + 文档。

#### Markdown 笔记双向链接（ROI 8.0）
- **用户需求度 4**：Obsidian 风格的 `[[wiki-link]]` 双向链接是知识管理工具的核心差异化功能。用户在 Markdown 文档中使用 `[[文档名]]` 引用其他文档，系统自动建立双向链接索引，支持反向链接查看。
- **技术可行性 4**：`regex` crate 已是依赖（用于 `[[link]]` 模式匹配）。`pulldown-cmark` 已是依赖（Markdown 解析）。需新增 `wiki_links` 表存储链接关系。导入时解析 `[[link]]` 并建立索引。前端在文档预览中渲染可点击链接。
- **预计天数 2**：解析器 + 存储层 + 反向链接查询 + 前端渲染 + 测试 + 文档。

#### 对话分支/版本树（ROI 6.0）
- **用户需求度 3**：现有 `turn-tree.js` + `message-edit.js` 已支持消息编辑版本切换（◀ 1/N ▶），但缺乏可视化的对话树视图。ChatGPT 风格的分支树让用户直观看到对话的所有分支路径，便于探索不同思路。
- **技术可行性 4**：`turn_active_versions` 表已存在。`ChatMessage` 已有 `turn_group` 和 `version` 字段。需新增树视图组件（纯 HTML/CSS 树形结构，零新增依赖）。
- **预计天数 2**：树数据模型 + 树视图前端 + 分支操作 + 测试 + 文档。

### 2.1 功能 1：本地知识图谱导出（REQ-EXP-006）

#### 用户场景

用户在知识图谱可视化面板中查看实体关系图后，希望将图谱数据导出为标准格式，用于：
1. 在 Gephi / Cytoscape 中进行高级网络分析
2. 在 Neo4j 中导入为图数据库
3. 作为知识库的结构化备份
4. 与其他知识图谱工具互操作

#### 技术方案

**推荐方案**：双格式导出（GraphML + JSON-LD），零新增依赖

- **GraphML**（XML 格式）：图交换标准格式，Gephi/Cytoscape/yEd 原生支持。手动生成 XML 字符串（GraphML 结构简单，无需 quick-xml 依赖）。
- **JSON-LD**（JSON 格式）：W3C 标准，Neo4j/语义 Web 工具支持。使用 `serde_json`（已有依赖）序列化。

**数据来源**：
- `entity_relations` 表：`list_all_relations(limit, offset)` → `Vec<EntityRelation>`
- `entities` 表：`list_all_entities()` → `Vec<Entity>`
- `GraphStats`：`get_graph_stats()` → 实体总数 + 关系总数 + 关系类型分布

> **互联网搜索引用**（铁律八）：
> - GraphML 规范：http://graphml.graphdrawing.org/
> - JSON-LD 规范：https://www.w3.org/TR/json-ld/
> - Gephi 支持 GraphML 导入：https://gephi.org/users/supported-graph-formats/
> - Neo4j 支持 JSON-LD：https://neo4j.com/docs/cypher-manual/current/json/

### 2.2 功能 2：文档摘要自动生成（REQ-ING-019）

#### 用户场景

用户导入文档后，系统自动调用 LLM 生成文档摘要（200-300 字），显示在文档列表中。用户无需打开对话即可快速了解每篇文档的核心内容，大幅提升知识库浏览效率。

#### 技术方案

**推荐方案**：导入管线集成 LLM 摘要生成

1. `Document` 结构体新增 `summary: Option<String>` 字段
2. `ImportService` 导入管线在嵌入完成后，异步调用 `LLMProvider` 生成摘要
3. 摘要 prompt：`请用 200-300 字总结以下文档的核心内容：\n\n{document_text}`
4. 摘要存储在 `documents` 表的 `summary` 列
5. 前端文档列表显示摘要（展开/折叠）
6. 支持手动重新生成摘要（切换 LLM 后）

**关键技术点**：
- 摘要生成是异步的，不阻塞导入流程（导入完成后 spawn 独立任务）
- 摘要生成失败不影响文档导入（优雅降级，`summary` 保持 `None`）
- 文档文本截断：取前 4000 字符作为摘要输入（避免超长文档 token 爆炸）
- LLM 非流式调用：使用 `LLMProvider` 的 `chat_stream()` 收集完整响应

> **互联网搜索引用**（铁律八）：
> - 文档摘要自动生成是知识管理工具的标准功能（Notion AI / Obsidian / Logseq）
> - 参考 AnythingLLM document summarization：https://docs.anythingllm.com/
> - 摘要 prompt 参考 Anthropic 的 summarization best practices

#### 依赖

无新增依赖（`LLMProvider` trait + `tokio::spawn` 已有）。

### 2.3 功能 3：对话模板/快捷指令系统（REQ-RAG-038）

#### 用户场景

用户希望创建自定义快捷指令模板，如：
- `/legal` → 法律条款分析模板：「请从以下内容中提取法律条款，分析适用条件、法律后果和例外情形：{query}」
- `/review` → 代码审查模板：「请审查以下代码的安全性、性能和可维护性：{query}」
- `/paper` → 论文摘要模板：「请总结这篇论文的研究问题、方法、主要发现和局限性：{query}」

现有 6 个硬编码指令（summary/compare/extract/translate/timeline/mindmap）无法满足垂直领域需求。

#### 技术方案

**推荐方案**：扩展 slash-commands.js + settings 表存储

1. 自定义模板数据模型：`PromptTemplate { id, name, label, desc, icon, prompt_template, created_at }`
2. 存储复用 settings 表 JSON 序列化模式（与 workflow 模板一致）：`template.{id}` 存储单个模板，`template.index` 存储模板 ID 列表
3. 后端 CRUD IPC 命令：`save_template` / `list_templates` / `delete_template`
4. 前端在 `slash-commands.js` 中合并系统指令 + 自定义模板
5. 新增模板管理面板（设置面板内或独立面板）

> - ChatGPT Custom Instructions：https://help.openai.com/en/articles/8096356
> - Obsidian Templates：https://help.obsidian.md/Plugins/Templates
> - 参考 AnythingLLM Prompt Templates：https://docs.anythingllm.com/

### 2.4 功能 4：Markdown 笔记双向链接（REQ-ING-020）

#### 用户场景

用户在 Markdown 文档中使用 `[[文档名]]` 语法引用知识库中的其他文档（Obsidian 风格 wiki-link）。系统自动：
1. 解析 `[[link]]` 并匹配知识库中的文档
2. 建立双向链接索引（正向链接 + 反向链接）
3. 在文档预览中渲染可点击链接
4. 在侧栏显示当前文档的反向链接列表

#### 技术方案

4. **查询**：`get_backlinks(doc_id)` 返回所有引用当前文档的文档列表

6. **文档名匹配**：模糊匹配（去掉扩展名后忽略大小写比较）

5. **面板入口**：对话区顶部新增「分支树」按钮，点击弹出树视图面板

### wiki_links 表（S57）

```sql
CREATE TABLE IF NOT EXISTS wiki_links (
    id TEXT PRIMARY KEY,
    source_doc_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    target_doc_name TEXT NOT NULL,
    target_doc_id TEXT REFERENCES documents(id) ON DELETE SET NULL,
    chunk_id TEXT NOT NULL REFERENCES chunks(id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_wiki_links_source ON wiki_links(source_doc_id);
CREATE INDEX IF NOT EXISTS idx_wiki_links_target ON wiki_links(target_doc_id);
```
