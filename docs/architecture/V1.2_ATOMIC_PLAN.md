### 1.3 评分依据

#### PDF 导出（ROI 20.0）
- **用户需求度 4**：对话/文档导出为 PDF 是知识管理工具的高频需求，用户反馈中多次提及。当前仅有 Markdown 导出（REQ-EXP-001），PDF 导出是自然延伸。
- **技术可行性 5**：Tauri v2 WebView 原生支持 `window.print()`，用户通过浏览器打印对话框「保存为 PDF」。零新增 Rust 依赖，纯前端 `@media print` CSS + 打印模板。`printpdf` crate（v0.12.5，MIT）作为备选方案（服务端生成 PDF），但 `window.print()` 方案更简洁且支持用户自定义页面设置。
- **预计天数 1**：打印模板 + `@media print` CSS + 导出按钮 + i18n + 测试。

#### .pptx 导入（ROI 12.0）
- **用户需求度 3**：演示文稿是知识工作者常用格式，但文本密度低于文档（以图片+要点为主），RAG 检索价值中等。
- **技术可行性 4**：`pptx-to-md` crate（v1.0.0，MIT/Apache-2.0）直接将 .pptx 转换为 Markdown，与 DocxLoader/HtmlLoader 实现模式完全一致。备选 `ppt-rs`（v0.2.24）更成熟但 API 更复杂。
- **预计天数 1**：PptxLoader 实现 + ALLOWED_EXTENSIONS 扩展 + 测试 + 前端/i18n 同步。

#### .epub 导入（ROI 12.0）
- **用户需求度 3**：电子书是知识管理的重要来源，技术文档/书籍常以 .epub 格式分发。
- **技术可行性 4**：`rbook` crate（v0.7.10，Apache-2.0，Rust 1.88+）支持 EPUB 2/3 读写，线程安全，API 清晰。备选 `epub` crate（v2.1.5）但 GPL-3.0 许可证不兼容 MIT 项目。
- **预计天数 1**：EpubLoader 实现 + ALLOWED_EXTENSIONS 扩展 + 测试 + 前端/i18n 同步。

#### 自定义嵌入模型上传（ROI 6.0，Pro 战略入选）
- **用户需求度 3**：高级用户（科研/法律/医疗）需要领域专用嵌入模型（如 bge-large、e5-large）。3 个预设模型覆盖通用场景，但垂直领域有刚需。
- **技术可行性 4**：fastembed 已支持 `UserDefinedEmbeddingModel` + `TokenizerFiles`（`local_embedder.rs` 已使用此 API）。主要工作：文件上传 UI + ONNX 格式验证 + 维度检测 + 设置持久化。
- **预计天数 2**：后端验证/加载逻辑 + 前端上传 UI + 测试 + 文档同步。
- **入选理由**：虽 ROI < 10，但作为 Pro 差异化功能具有战略价值，且技术基础设施已就绪（fastembed UserDefinedEmbeddingModel）。

## Phase 2: Top 4 功能技术调研

### 2.1 功能 1：PDF 导出（REQ-EXP-002）

#### 用户场景

用户希望将对话内容或知识库文档导出为 PDF 文件，用于分享、归档或打印。当前仅有 Markdown 导出（REQ-EXP-001），PDF 是更通用的分发格式。

#### 技术方案

**推荐方案**：Tauri WebView `window.print()` + `@media print` CSS

- 前端创建打印专用 HTML 模板（对话/文档内容 + 排版优化）
- 添加 `@media print` CSS 规则（隐藏导航/侧栏/输入框，优化字体/间距/分页）
- 调用 `window.print()` 触发浏览器原生打印对话框
- 用户选择「保存为 PDF」完成导出
- 零新增 Rust 依赖

**备选方案 A**：`printpdf` crate（v0.12.5，MIT）+ HTML 特性
- 支持从 HTML 生成 PDF（`html` feature）
- 优点：服务端生成，不依赖浏览器
- 缺点：需要 fontconfig 系统依赖，字体渲染质量不如浏览器

**备选方案 B**：`headless_chrome` crate（v1.0.22）
- 使用无头 Chrome 渲染 HTML → PDF
- 优点：渲染质量最高
- 缺点：需要 Chrome/Chromium 系统依赖，体积大，不适合桌面应用

**方案对比**：

| 方案 | 新增依赖 | 渲染质量 | 系统依赖 | 实现复杂度 | 推荐 |
|---|---|---|---|---|---|
| `window.print()` | 无 | 高（浏览器原生） | 无 | 低 | ✅ |
| `printpdf` | 1 crate | 中 | fontconfig | 中 | ❌ |
| `headless_chrome` | 1 crate | 最高 | Chrome | 高 | ❌ |

> **铁律九**：`window.print()` 方案零新增依赖，利用 Tauri WebView 原生能力，是最符合 Rust 生态优先原则的方案。

> **互联网搜索引用**（铁律八）：
> - Tauri v2 WebView 基于 Wry（macOS WKWebView / Windows WebView2 / Linux WebKitGTK），均原生支持 `window.print()`
> - 参考 AnythingLLM 实现：使用浏览器打印对话框导出 PDF（https://docs.anythingllm.com/）
> - 参考 Open WebUI：提供 `window.print()` 导出选项（https://docs.openwebui.com/）

#### 依赖

无新增依赖（纯前端 CSS + JS）。

### 2.2 功能 2：.pptx 导入（REQ-ING-017）

#### 用户场景

用户导入 Microsoft PowerPoint 演示文稿（.pptx），提取每张幻灯片的文本内容（标题、要点、备注），纳入知识库进行 RAG 检索。

#### 技术方案

**推荐方案**：`pptx-to-md` crate（v1.0.0，MIT/Apache-2.0）

- 直接将 .pptx 转换为 Markdown 文本
- 提取幻灯片标题（→ `#` 标题）、要点（→ `-` 列表）、备注
- 图片以 `[图片]` 占位符替代（与 DocxLoader 一致）
- 表格转换为 Markdown 表格

**备选方案**：`ppt-rs` crate（v0.2.24）
- 更成熟的 PowerPoint 读写库
- 但 API 更底层，需要手动遍历幻灯片元素
- 实现工作量更大

**方案对比**：

| 方案 | 版本 | 许可证 | 纯 Rust | 输出格式 | 推荐 |
|---|---|---|---|---|---|
| `pptx-to-md` | 1.0.0 | MIT/Apache-2.0 | ✅ | Markdown | ✅ |
| `ppt-rs` | 0.2.24 | MIT | ✅ | 结构化数据 | ❌ |

> **铁律六**：`cargo search pptx` 确认 `pptx-to-md` v1.0.0 为最新版本（2026-08-06 确认）。
>
> **铁律九**：`pptx-to-md` 为纯 Rust crate，直接输出 Markdown，与现有 DocxLoader/HtmlLoader 实现模式完全一致。

> **互联网搜索引用**（铁律八）：
> - .pptx 格式基于 Office Open XML（OOXML），ZIP 包含 `ppt/slides/slide1.xml` 等
> - 参考 python-pptx（Python 生态最成熟的 PPTX 库）：https://python-pptx.readthedocs.io/
> - pptx-to-md 基于 Rust 解析 OOXML ZIP + XML 遍历

### 2.3 功能 3：.epub 导入（REQ-ING-018）

#### 用户场景

用户导入电子书（.epub 格式），提取章节文本纳入知识库。EPUB 是技术书籍、学术论文、小说的常见分发格式。

#### 技术方案

**推荐方案**：`rbook` crate（v0.7.10，Apache-2.0，Rust 1.88+）

- 支持 EPUB 2 和 EPUB 3 格式
- 线程安全（`threadsafe` feature）
- 支持读取（`read` feature）和写入（`write` feature）
- API 清晰：`Epub::new(path)` → 遍历 spine（阅读顺序）→ 提取每章 XHTML 内容
- XHTML → 纯文本转换（复用 `html2text` crate，已依赖）

**备选方案**：`epub` crate（v2.1.5，GPL-3.0）
- 功能更完整但 GPL-3.0 许可证与 EchoMind MIT 许可证不兼容
- 排除

**方案对比**：

| 方案 | 版本 | 许可证 | 纯 Rust | EPUB 3 | 推荐 |
|---|---|---|---|---|---|
| `rbook` | 0.7.10 | Apache-2.0 | ✅ | ✅ | ✅ |
| `epub` | 2.1.5 | GPL-3.0 | ✅ | ✅ | ❌（许可证不兼容） |

> **铁律六**：`cargo search epub` 确认 `rbook` v0.7.10 为最新版本（2026-08-06 确认）。
>
> **铁律九**：`rbook` 为纯 Rust crate，Apache-2.0 许可证兼容。
>
> **互联网搜索引用**（铁律八）：
> - EPUB 格式规范：https://www.w3.org/publishing/epub/
> - EPUB 本质是 ZIP 包含 XHTML + CSS + 图片 + metadata.opf（清单）+ toc.ncx（目录）
> - rbook 文档：https://docs.rs/rbook

#### EpubLoader 实现规格

```rust
/// .epub 电子书加载器（REQ-ING-018）：基于 rbook 解析 EPUB 2/3。
/// 按 spine 顺序遍历章节，XHTML → 纯文本（复用 html2text）。
/// 每章以 `---` 分隔，章节标题转为 `#`。
pub struct EpubLoader;

impl EpubLoader {
    fn extract(file_path: &str) -> anyhow::Result<String> {
        // 1. rbook::Epub::new(file_path) 打开 EPUB
        // 2. 获取 spine（阅读顺序的 manifest items）
        // 3. 遍历每章：读取 XHTML 内容 → html2text 转纯文本
        // 4. 提取章节标题（<h1>/<title>）作为 Markdown 标题
        // 5. 合并所有章节，--- 分隔
    }
}

impl Loader for EpubLoader {
    async fn load(&self, file_path: &str) -> anyhow::Result<String> {
        let owned = file_path.to_string();
        tokio::task::spawn_blocking(move || Self::extract(&owned))
            .await
            .context("EpubLoader 解析任务执行失败")
    }
}
```

### 2.4 功能 4：自定义嵌入模型上传（REQ-VEC-014，Pro）

#### 用户场景

Pro 用户上传自己的 ONNX 嵌入模型（如 `bge-large-zh-v1.5`、`e5-large-v2`、领域专用微调模型），替代 3 个预设模型。适用于法律、医疗、科研等垂直领域，通用预设模型无法满足精度要求。

#### 技术方案

**推荐方案**：复用 fastembed `UserDefinedEmbeddingModel` API

`local_embedder.rs` 已使用 `UserDefinedEmbeddingModel` + `TokenizerFiles` + `InitOptionsUserDefined` 加载预设模型。自定义模型上传只需：

1. 用户上传文件：ONNX 模型文件（`model.onnx` 或 `model_quantized.onnx`）+ tokenizer 文件（`tokenizer.json` / `tokenizer_config.json` / `vocab.txt` 等）
2. 后端验证：检查 ONNX 文件格式 + 检测嵌入维度（运行一次推理获取 `vec.len()`）
3. 存储：保存到 `{data_dir}/custom_models/{model_name}/`
4. 加载：通过 `UserDefinedEmbeddingModel::new()` 加载，与预设模型路径一致
5. 切换：`EmbeddingModel` 枚举新增 `Custom(String)` 变体

**关键技术点**：
- fastembed `UserDefinedEmbeddingModel` 接受 `Vec<u8>`（ONNX 字节）+ `TokenizerFiles`（tokenizer 文件路径）
- 维度检测：首次加载后运行 `embed("test")` 获取向量长度，存入 settings
- 模型验证：检查 ONNX 文件 magic bytes（`08 00` = ONNX 格式）
- 文件大小限制：建议 ≤ 500MB（ONNX 量化模型通常 30-150MB）

> **互联网搜索引用**（铁律八）：
> - fastembed 自定义模型文档：https://docs.rs/fastembed/latest/fastembed/#user-defined-models
> - HuggingFace ONNX 模型格式：`model.onnx`（FP32）+ `model_quantized.onnx`（INT8 量化）
> - 参考 AnythingLLM 自定义嵌入：https://docs.anythingllm.com/
> - 参考 Open WebUI 嵌入模型配置：https://docs.openwebui.com/
