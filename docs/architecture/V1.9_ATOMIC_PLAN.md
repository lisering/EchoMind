## 2. 选定功能

### 2.1 S1: 检索 & LLM 参数可配置（REQ-RAG-014 + REQ-RAG-015）

**背景**：当前 `DEFAULT_TOP_K = 8` 硬编码，`score_threshold` 在 `VectorRetriever` 中不可配置，`OpenAIProvider` 不传递 temperature/max_tokens/top_p。用户无法调优检索和生成行为。

**目标**：用户在设置面板配置检索参数（top_k 1-20、相似度阈值 0.0-1.0、Chunk Expansion 开关）和 LLM 生成参数（temperature 0.0-2.0、max_tokens 256-8192、top_p 0.0-1.0），参数持久化到 settings 表，对新查询生效。

**新增 settings 键**：
| 键 | 类型 | 默认值 | 范围 |
|---|---|---|---|
| `rag.top_k` | int | 8 | 1-20 |
| `rag.score_threshold` | float | 0.0 | 0.0-1.0 |
| `rag.chunk_expansion_enabled` | bool | true | — |
| `rag.chunk_expansion_window` | int | 1 | 0-3 |
| `llm.temperature` | float | 0.7 | 0.0-2.0 |
| `llm.max_tokens` | int | 4096 | 256-8192 |
| `llm.top_p` | float | 1.0 | 0.0-1.0 |

**新增 IPC 命令**（4 个 Free）：
- `get_rag_params() -> RagParams` — 获取检索参数
- `set_rag_params(params: RagParams) -> ()` — 设置检索参数
- `get_generation_params() -> GenerationParams` — 获取 LLM 生成参数
- `set_generation_params(params: GenerationParams) -> ()` — 设置 LLM 生成参数

**新增数据模型**：
```rust
// crates/models/src/lib.rs
pub struct RagParams {
    pub top_k: usize,           // 1-20, default 8
    pub score_threshold: f32,   // 0.0-1.0, default 0.0
    pub chunk_expansion_enabled: bool,  // default true
    pub chunk_expansion_window: usize,   // 0-3, default 1
}

pub struct GenerationParams {
    pub temperature: f32,   // 0.0-2.0, default 0.7
    pub max_tokens: usize,  // 256-8192, default 4096
    pub top_p: f32,         // 0.0-1.0, default 1.0
}
```

**TDD 测试计划**（7 个测试）：
| TC ID | 描述 |
|---|---|
| TC-RAG-PARAMS-001 | `RagParams::default()` 返回 top_k=8, threshold=0.0, expansion=true, window=1 |
| TC-RAG-PARAMS-002 | 自定义 top_k 从 settings 表读取覆盖 DEFAULT_TOP_K |
| TC-RAG-PARAMS-003 | score_threshold > 0 过滤低分检索结果 |
| TC-RAG-PARAMS-004 | chunk_expansion_enabled=false 禁用相邻扩展 |
| TC-LLM-PARAMS-001 | `GenerationParams::default()` 返回 temp=0.7, max_tokens=4096, top_p=1.0 |
| TC-LLM-PARAMS-002 | 自定义参数包含在 OpenAIProvider 请求 JSON body 中 |
| TC-LLM-PARAMS-003 | 参数持久化到 settings 表并可通过 IPC 读写 |

### 2.2 S2: 文档列表排序（REQ-ING-008）

**背景**：当前文档列表按导入时间倒序排列（固定），用户无法按文件名或文件大小排序。

**目标**：文档列表支持按导入时间（默认倒序）、文件名（A-Z / Z-A）、文件大小排序，排序状态在当前会话内保持。

**新增 IPC 参数**：
- `list_documents(sort_by: Option<String>, sort_order: Option<String>)` — 扩展现有命令

**排序维度**：
| sort_by | sort_order | SQL |
|---|---|---|
| `imported_at` (默认) | `desc` (默认) | `ORDER BY imported_at DESC` |
| `imported_at` | `asc` | `ORDER BY imported_at ASC` |
| `file_name` | `asc` | `ORDER BY file_name ASC` |
| `file_name` | `desc` | `ORDER BY file_name DESC` |
| `file_size` | `desc` | `ORDER BY file_size DESC` |
| `file_size` | `asc` | `ORDER BY file_size ASC` |

**TDD 测试计划**（3 个测试）：
| TC ID | 描述 |
|---|---|
| TC-ING-SORT-001 | 默认排序：imported_at desc（最新在前） |
| TC-ING-SORT-002 | file_name asc：A-Z 字母序 |
| TC-ING-SORT-003 | file_size desc：大文件在前 |

### 2.3 S3: DS-03 Session Strip — 手动会话压缩

**背景**：DS4 的 `/strip` 命令移除会话的 KV cache payload 保留文本。EchoMind 适配为：用户手动触发会话压缩——删除指定位置之前的所有消息，生成摘要并作为 system 消息插入，保留最近 N 条消息原文。

**目标**：用户在对话中点击"压缩会话"按钮，系统：
1. 保留最近 `keep_count` 条消息（默认 6 条）
2. 对之前的消息调用 LLM 生成摘要
3. 删除旧消息，插入摘要作为 system 消息
4. 持久化到 messages 表

**新增 IPC 命令**（1 个 Free）：
- `strip_conversation(conversation_id: String, keep_count: Option<usize>) -> StripResult`

**新增数据模型**：
```rust
pub struct StripResult {
    pub stripped_count: usize,  // 删除的消息数
    pub summary: String,        // 生成的摘要
    pub kept_count: usize,      // 保留的消息数
}
```

**TDD 测试计划**（4 个测试）：
| TC ID | 描述 |
|---|---|
| TC-STRIP-001 | 压缩删除 keep_count 之前的消息 |
| TC-STRIP-002 | 压缩生成被删除消息的摘要 |
| TC-STRIP-003 | 压缩后保留最近 keep_count 条消息 + 摘要 system 消息 |
| TC-STRIP-004 | 空会话或消息数 ≤ keep_count 时为 no-op |
