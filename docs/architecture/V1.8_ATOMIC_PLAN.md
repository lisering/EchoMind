## 1. F5-F8 评估结论

### 1.1 F5: OM3 Scored Selector 集成（ROI 4.2）→ ⏸ 推迟到 v2.0

**实现状态**：`crates/core/src/scored_selector.rs` 完全实现（12 TDD 测试），`LlmRouter::resolve_scored()` 已实现。

**当前使用**：`chat_inner` 使用 `state.llm_router.resolve()`（简单模式路由），未调用 `resolve_scored()`。

**阻碍原因**：
- EchoMind 架构只支持单一 LLM 配置（`AppState.llm_config` 为单个 `Option<LlmConfig>`）
- 多 provider 路由需要：
  1. 多 LLM 配置存储（`Vec<LlmConfig>` 替代 `Option<LlmConfig>`）
  2. 前端 UI 配置多个 provider
  3. `ProviderCandidate` 列表构建逻辑
- 这是架构级变更，不适合 v1.8 小版本

**结论**：推迟到 v2.0（需多 provider 架构重构）。

### 1.2 F6: B01/B02 SystemContext+Epoch（ROI 4.1）→ ⏸ 推迟到 v2.0

**实现状态**：`crates/context/` 完全实现（16 TDD 测试：`SystemContext` + `ContextEpochManager` + 5 内置 Source）。

**当前使用**：`chat_inner` 直接调用 `build_rag_prompt_segmented()` 构建系统提示词，未经过 `ContextEpochManager`。

**阻碍原因**：
- 集成需要：
  1. 创建具体 `ContextSource` 实现（从 `Storage` 加载 KB 摘要/对话历史/检索记忆等）
  2. 添加 `context_epochs` SQLite 表 + 持久化逻辑
  3. 替换 `chat_inner` 中的 prompt building 为 `ContextEpochManager::prepare()`
  4. Mid-Conversation System Message 事件推送
- 当前 `build_rag_prompt_segmented()` 简单有效，替换风险高、收益增量小
- 这是 chat 启动流程的重大重构

**结论**：推迟到 v2.0（需 chat flow 重构）。

### 1.3 F7: DS-01 PromptCache 集成（ROI 4.0）→ ⏸ 推迟到 v2.0

**实现状态**：`crates/infra/src/prompt_cache.rs` 完全实现（27 TDD 测试：KPC 格式 + SHA1 匹配 + LRU 驱逐 + 边界裁剪 + 原子写入）。

**当前使用**：未集成到 `LocalLlmEngine` 或 `OpenAIProvider`。

**阻碍原因**：
- mistral.rs v0.9.0 API 不暴露 `tokenize()` 或 prompt prefix caching 接口
  - `LocalLlmEngine` 使用 `RequestBuilder` + `Model::stream_chat_request()`
  - 无 `tokenize()` 方法可将文本转为 token IDs
  - 无 `inject_prefix()` 方法可注入预 tokenize 的前缀
- `PromptCache` 存储的 token IDs 无消费方
- Remote (OpenAI) 路径：API 服务端已通过 `chat_stream_segmented()` 处理 prefix caching（两条独立 system 消息），本地 `PromptCache` 无增量价值

**结论**：推迟到 v2.0（需 mistral.rs API 暴露 tokenize 或 CustomGemv 完整前向传播实现）。

### 1.4 F8: B04 CachePolicy 集成（ROI 3.7）→ ⏸ 推迟到 v2.0

**实现状态**：`crates/prompt/src/cache_policy.rs` 完全实现（6 TDD 测试：`CachePolicy` + `apply_cache_policy` + `CachedSegmentedPrompt`）。

**当前使用**：未集成到 prompt 构建流程。

**阻碍原因**：
- `OpenAIProvider` 已通过 `chat_stream_segmented()` 实现隐式 prompt caching（`static_prefix` 作为独立 system 消息）
- `CachePolicy` 添加显式断点标注（`CacheBreakpoint::After`），但 OpenAI-compatible API 无显式 cache breakpoint 参数
- 唯一受益场景：Anthropic API 的 `cache_control` 参数（当前不支持）
- 集成 `apply_cache_policy()` 到 `build_rag_prompt_segmented()` 是 no-op（不产生实际性能提升）

**结论**：推迟到 v2.0（需 Anthropic 显式 cache control API 支持）。

## 2. v1.8 选定功能

### 2.1 B09 Skill 系统集成（V1.7 标注 "v1.8+"）

**背景**：`crates/core/src/skill.rs` 已实现 Skill 发现（5 TDD 测试 + 2 doctest），`discover_from_dir()` 可异步扫描目录。但未集成到斜杠命令系统——用户无法在 `/` 命令面板中使用 Skill。

**目标**：用户在 `{data_dir}/skills/` 目录放置 `.md` 文件（YAML frontmatter `slash: true`），自动出现在 `/` 命令面板。选中后 Skill 内容作为 system prompt 注入对话。

**实现规格**：

```
输入：{data_dir}/skills/*.md 文件（YAML frontmatter: name + description + slash: true）
输出：斜杠命令面板显示 Skill 指令，选中后 Skill.content 注入对话
边界：目录不存在 → 空列表（静默降级）；文件解析失败 → 跳过
错误处理：IO 失败 → 空列表 + 日志告警
```

**实现步骤**：
1. S2: 后端 `discover_skills` IPC 命令 — 调用 `Skill::discover_from_dir(data_dir/skills)`，过滤 `slash == true`
2. S3: 前端 `slash-commands.js` 加载 Skills — `loadSkills()` IPC 调用 + 合并到 `getAllCommands()`
3. S4: 前端 `chat.js` send() 集成 — Skill 指令选中后注入 content 到 system prompt

**TDD 测试**：
- TC-SKILL-INTEGRATE-001: `discover_skills` IPC 返回 `slash: true` 的 Skill 列表
- TC-SKILL-INTEGRATE-002: 目录不存在时返回空列表（静默降级）
- TC-SKILL-INTEGRATE-003: `slash: false` 的 Skill 不出现在斜杠命令面板
