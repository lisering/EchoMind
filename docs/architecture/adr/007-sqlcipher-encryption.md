# ADR-007: SQLCipher AES-256 透明加密

> **状态**：✅ 已采纳
> **日期**：2026-07-26
> **决策者**：Chief Architect / Security Officer

## 背景

EchoMind 面向律师、研究人员等高隐私用户。数据库中存储的文档可能包含敏感信息（合同、案例、研究数据）。需要：

- **静态加密**：数据库文件在磁盘上加密，即使文件被复制也无法读取
- **用户密码控制**：加密密钥由用户密码派生，无后门
- **透明加密**：应用层无感知，SQL 操作照常使用
- **密钥安全**：密码在内存中用后即清（zeroize）
- **暴力破解防护**：限制解锁尝试次数

## 决策

采用 SQLCipher + Argon2id KDF：

- **SQLCipher**：SQLite 扩展，提供 AES-256-CBC 透明加密
- **密钥派生**：Argon2id（m=19456KB, t=2, p=1）→ 32 字节密钥
- **PBKDF2 回退**：如果 Argon2id 不可用，降级为 PBKDF2（210000 迭代）
- **PRAGMA key**：SQLCipher 透明加密，SQL 操作无需修改
- **SecureString**：密码用 `zeroize` crate 在 drop 时清零内存
- **安全状态机**：`Unencrypted → EncryptedUnlocked → Locked`
- **自动锁屏**：空闲超时自动锁定，`record_activity()` 重置计时器
- **暴力破解防护**：5 次失败 → 指数退避（30s → 60s → 120s → ...）
- **剪贴板自动清除**：敏感数据复制后 30s 自动清空

## 考虑的替代方案

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| 文件级加密（LUKS/dm-crypt） | OS 级保护 | 不跨平台，用户需配置 | 平台限制 |
| 应用层加密（加密字段值） | 灵活选择字段 | 查询性能差，无法全文搜索 | 功能限制 |
| age 加密 + SQLite | 简单 | 需手动加解密，非透明 | UX 差 |
| 不加密 | 零开销 | 无安全保护 | 不满足需求 |

## 后果

- 正面：数据库文件即使被复制也无法解密（无密码）
- 正面：Argon2id 提供抗 GPU/ASIC 暴力破解
- 正面：透明加密，应用层代码无修改
- 正面：自动锁屏 + 暴力破解防护 + 剪贴板清除构成完整安全链
- 正面：SecureString 确保密码在内存中不留痕迹
- 负面：SQLCipher 增加二进制体积（C 扩展）
- 负面：加密数据库性能略降（约 5-10% 开销）
- 负面：忘记密码 = 数据永久丢失（无后门）
