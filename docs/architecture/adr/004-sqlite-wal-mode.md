# ADR-004: SQLite WAL 模式 + r2d2 连接池

> **状态**：✅ 已采纳
> **日期**：2026-07-25
> **决策者**：Chief Architect

## 背景

EchoMind 需要一个嵌入式数据库存储文档、分块、向量、会话和设置。作为本地优先（local-first）的桌面应用，数据库需要满足：

- 零配置（无需安装外部数据库服务）
- 单文件存储（便于备份和迁移）
- 支持并发读取（RAG 检索 + UI 列表 + 导入管线同时运行）
- 写入不阻塞读取（用户对话时不卡 UI）
- 支持全文搜索（BM25 混合检索）
- 支持加密（SQLCipher AES-256）

## 决策

采用 SQLite + WAL（Write-Ahead Logging）模式 + r2d2 连接池：

- **WAL 模式**：`PRAGMA journal_mode = WAL` — 读写不互斥，写入不阻塞读取
- **r2d2 连接池**：多个并发操作各持有一个连接，避免 `Mutex<Connection>` 串行化
- **busy_timeout = 5s**：写入竞争时等待而非立即失败
- **FTS5 虚拟表**：BM25 全文搜索用于混合检索
- **BLOB 存储**：向量以原始 f32 小端字节存储，余弦相似度在 Rust 中计算
- **所有 DB 操作经 `tokio::task::spawn_blocking`**：避免阻塞 tokio 异步运行时

## 考虑的替代方案

| 方案 | 优点 | 缺点 | 为什么没选 |
|---|---|---|---|
| PostgreSQL | 功能更强 | 需要外部服务，不符合本地优先 | 违反零配置原则 |
|sled | 纯 Rust | 生态不成熟，无全文搜索 | 功能不足 |
| LMDB | 极快 | 单写入者，不适合并发写入 | 并发限制 |
| DuckDB | 分析型强 | 嵌入式 OLAP，不适合 OLTP | 用例不匹配 |

## 后果

- 正面：零配置，单文件 `.db` 便于备份
- 正面：WAL 模式读写并发性能优秀
- 正面：r2d2 连接池自动管理连接生命周期
- 正面：FTS5 内置 BM25 排名，无需额外索引
- 正面：SQLCipher 兼容（PRAGMA key 透明加密）
- 负面：向量搜索是全表扫描（O(n)），大知识库需 HNSW 优化
- 负面：SQLite 不支持向量原生类型，需 BLOB 序列化
