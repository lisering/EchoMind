### 1.3 评估维度说明

- **用户价值 (40%)**：功能对用户的直接帮助程度（律师/研究者日常使用场景）
- **实现易度 (30%)**：代码复杂度、新增依赖、改动范围（越高越容易）
- **架构收益 (20%)**：对代码架构的改善、可复用性、技术债减少
- **风险控制 (10%)**：引入 bug 的风险、数据安全、向后兼容性

## 2. 选定功能

### 2.1 S1: 离线模式降级（REQ-ERR-003）

**目标**：应用检测网络状态变化，离线时在侧栏显示离线指示器，输入框 placeholder 变为提示文案，发送按钮禁用。恢复在线后自动恢复正常 UI。

**纯前端实现**：
- `ui/src/offline-detector.js`：新建离线检测模块
  - 监听 `navigator.onLine` + `online`/`offline` 事件
  - 离线时：侧栏底部显示 `⚠ 离线` 指示器（amber 色）
  - 离线时：`#queryInput` placeholder 变为离线提示
  - 离线时：`#sendBtn` 添加 `disabled` 属性
  - 离线时：`#inputHint` 显示「离线模式 — 请检查网络连接」
  - 在线时：恢复所有元素原始状态
- `ui/index.html`：离线指示器容器
- `ui/styles/components.css`：离线指示器样式

### 2.3 S3: 应用更新检查（REQ-HELP-004）

### 2.4 S4: 性能指标采集（REQ-OBS-002）

**目标**：应用在关键操作处采集性能指标并记录到日志。导入耗时（解析/分块/嵌入各阶段）、检索耗时（向量搜索/关键词搜索/RRF 融合）、LLM 首 token 延迟、LLM 总生成耗时、冷启动耗时。指标以 INFO 级别日志记录，含操作类型、耗时(ms)、数据规模。

**后端**：
- 新增 `crates/core/src/perf_metrics.rs`：性能指标采集模块
  - `PerfMetric` 结构体（operation/duration_ms/data_size/timestamp）
  - `record_metric()` 函数 → tracing::info! 日志输出
  - `start_timer()` / `elapsed_ms()` 计时辅助
- 在关键位置注入 tracing 调用：
  - `import.rs`：解析/分块/嵌入各阶段
  - `retriever.rs`：向量搜索/关键词搜索
  - `hybrid_retriever.rs`：RRF 融合
  - `chat.rs`：首 token 延迟/总生成耗时
  - `lib.rs`：冷启动耗时
