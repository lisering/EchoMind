# EchoMind Pro 功能 ROI 评估报告

> **评估日期**：2026-08-24 ｜ **评估人**：AI Agent (S98)
>
> **关联文档**：`docs/SRS_v1.0.md` §6 ｜ `docs/architecture/V3.0_ATOMIC_PLAN.md` ｜ P0-3
>
> **评估目的**：对 14 个 Pro 功能逐一评估用户需求度 × 技术维护成本 × 差异化价值，决定保留 Pro 门控 / 下沉 Free / Deprecated。

---

## 1. 评估方法论

### 1.1 评估维度（三维度加权）

| 维度 | 权重 | 评分标准 |
|---|---|---|
| **用户需求度** | 40% | 1=极少用户需要，5=核心刚需。基于目标用户画像（律师/研究员/知识工作者）判断 |
| **技术维护成本** | 30% | 1=维护成本高（频繁 break / 依赖不稳定），5=维护成本低（稳定成熟） |
| **差异化价值** | 30% | 1=Free 版已覆盖类似能力，5=Free 版完全无法替代 |

### 1.2 决策矩阵

| 综合得分 | 决策 | 含义 |
|---|---|---|
| ≥ 4.0 | **保留 Pro** | 高价值 Pro 功能，继续门控 |
| 3.0 ~ 3.9 | **保留 Pro** | 中等价值，维持现状 |
| 2.0 ~ 2.9 | **考虑下沉** | 可在后续版本下沉 Free，扩大用户基数 |
| < 2.0 | **Deprecated** | 低价值或高成本，考虑废弃或替代 |

### 1.3 ROI 公式

```
ROI = (用户需求度 × 0.4 + 技术维护成本 × 0.3 + 差异化价值 × 0.3)
```

## 2. 14 个 Pro 功能逐一评估

### 2.1 本地 LLM 推理（mistral.rs，REQ-LLM-003）

| 维度 | 评分 | 说明 |
|---|---|---|
| 用户需求度 | 5 | 隐私敏感用户（律师/研究员）核心刚需：完全离线推理，零网络请求 |
| 技术维护成本 | 2 | mistral.rs v0.9.0 git 依赖，candle-core 不稳定；GPU 特性 break 频繁 |
| 差异化价值 | 5 | Free 版仅有 Remote LLM，本地推理是完全不可替代的隐私能力 |
| **ROI** | **4.1** | **保留 Pro** ✅ |

**决策理由**：EchoMind 的核心定位是「隐私优先的本地 RAG 知识库」，本地 LLM 推理是差异化竞争力的基石。尽管 mistral.rs 维护成本高，但这是 Pro 用户最核心的付费动机。

---

### 2.2 GPU 加速 Metal/CUDA（REQ-LLM-005）

| 维度 | 评分 | 说明 |
|---|---|---|
| 用户需求度 | 4 | 有 GPU 的高级用户需要加速本地推理；CPU 推理也可用但慢 |
| 技术维护成本 | 2 | Metal/CUDA 特性 break 频繁，跨平台测试困难 |
| 差异化价值 | 4 | 免费版无法提供 GPU 加速，但 CPU 推理已可用 |
| **ROI** | **3.4** | **保留 Pro** ✅ |

**决策理由**：GPU 加速是本地 LLM 推理的增强功能，与 REQ-LLM-003 绑定。维持 Pro 门控合理，但应关注 mistral.rs GPU 特性的稳定性。

---

### 2.3 采样参数配置（REQ-LLM-006）

| 维度 | 评分 | 说明 |
|---|---|---|
| 用户需求度 | 3 | 高级用户需要调参（temperature/top_p/top_k），普通用户不关心 |
| 技术维护成本 | 4 | 纯参数传递，维护成本低 |
| 差异化价值 | 2 | Remote LLM 模式也有采样参数，差异不大 |
| **ROI** | **3.0** | **保留 Pro** ✅（边缘） |

**决策理由**：虽然维护成本低，但差异化价值不高。保留 Pro 作为本地 LLM 的附属功能，不单独下沉。

---

### 2.4 自研量化推理内核（GEMV，REQ-LLM-007）

| 维度 | 评分 | 说明 |
|---|---|---|
| 用户需求度 | 2 | 仅影响本地 LLM 推理速度，用户不感知底层实现 |
| 技术维护成本 | 1 | 6 个模块（gguf_reader/quant_blocks/gemv_kernel/weight_repack/layer_prefetch/memory_budget），维护成本极高 |
| 差异化价值 | 3 | mistral.rs 已含量化支持，自研内核是性能优化而非功能差异 |
| **ROI** | **2.0** | **考虑下沉** ⚠️ |

**决策理由**：自研 GEMV 内核是在 mistral.rs 之上的一层性能优化，维护成本极高（6 模块 ~2000 行代码），但用户感知度低。建议在 v3.1+ 评估是否保留或下沉为 Free（因为它们不影响核心功能，只是加速）。当前维持 Pro 门控。

---

### 2.5 内存层次流式加载（REQ-LLM-008）

| 维度 | 评分 | 说明 |
|---|---|---|
| 用户需求度 | 2 | 大模型（>4GB）在低 RAM 设备上的可用性优化 |
| 技术维护成本 | 2 | madvise + 后台线程 + LRU 驱逐，跨平台兼容性复杂 |
| 差异化价值 | 3 | mistral.rs 自身有内存管理，自研层是增强 |
| **ROI** | **2.3** | **保留 Pro** ✅（与 LLM 推理绑定） |

**决策理由**：与 GEMV 内核同为本地 LLM 性能优化。维护成本较高但与 Pro 本地推理深度绑定。维持 Pro。

---

### 2.6 KV Cache 跨会话复用（REQ-LLM-009）

| 维度 | 评分 | 说明 |
|---|---|---|
| 用户需求度 | 3 | 多会话切换时加速首次响应，有感知但非刚需 |
| 技术维护成本 | 3 | 磁盘序列化格式 + 原子写入，中等复杂度 |
| 差异化价值 | 3 | Remote LLM 无法缓存 KV（API 无状态），本地独有 |
| **ROI** | **3.0** | **保留 Pro** ✅ |

**决策理由**：本地 LLM 独有优化，Remote LLM 无法实现。维持 Pro 作为本地推理的增强特性。

---

### 2.7 GGUF 模型文件管理（REQ-LLM-004）

| 维度 | 评分 | 说明 |
|---|---|---|
| 用户需求度 | 4 | 本地 LLM 用户必须能下载/管理模型文件 |
| 技术维护成本 | 4 | 下载/列表/删除，逻辑简单稳定 |
| 差异化价值 | 3 | 仅在本地 LLM 模式下需要 |
| **ROI** | **3.7** | **保留 Pro** ✅ |

**决策理由**：与本地 LLM 推理（REQ-LLM-003）配套，无独立下沉价值。

---

### 2.8 PDF 多模态导入（pdfium + OCR + VLM，REQ-MM-001~004）

| 维度 | 评分 | 说明 |
|---|---|---|
| 用户需求度 | 5 | PDF 是知识管理最核心格式，扫描版 PDF 必须 OCR |
| 技术维护成本 | 2 | pdfium-render + ocrs/rten + image 依赖链，编译重 |
| 差异化价值 | 5 | Free 版 PDF 仅纯文本提取，扫描版完全不可用 |
| **ROI** | **4.1** | **保留 Pro** ✅ |

**决策理由**：PDF 多模态是 Pro 用户第二大付费动机（仅次于本地 LLM）。扫描版 PDF OCR 是完全不可替代的能力。维持 Pro 门控。

---

### 2.9 BYOK VLM 图片理解（REQ-MM-003）

| 维度 | 评分 | 说明 |
|---|---|---|
| 用户需求度 | 3 | 图表/流程图理解有需求，但非核心 |
| 技术维护成本 | 3 | HTTP API 调用，逻辑简单 |
| 差异化价值 | 4 | Free 版无 VLM 能力，Pro 独有 |
| **ROI** | **3.3** | **保留 Pro** ✅ |

**决策理由**：VLM 是多模态 PDF 导入的增强层。维持 Pro 作为 PDF 多模态的可选增强。

### 2.10 ColBERT 多向量嵌入（REQ-PERF-008）

|---|---|---|

| 技术维护成本 | 3 | fastembed 多向量模式，中等复杂度 |

### 2.11 ONNX 嵌入压缩器（REQ-PERF-002）

| 用户需求度 | 2 | Prompt 压缩增强，用户无感知 |

## 3. 评估汇总

### 3.1 决策分布

| 决策 | 数量 | 功能 |
|---|---|---|
| **保留 Pro** | 10 | 本地 LLM 推理 / GPU 加速 / 采样参数 / KV Cache / GGUF 管理 / PDF 多模态 / VLM / tree-sitter / 文档审计 / 内存流式加载 |
| **考虑下沉** | 4 | 自研 GEMV 内核 / ColBERT 多向量 / ONNX 压缩器 / WasmExecutor |
| **Deprecated** | 0 | — |

### 3.2 ROI 排名

| 排名 | 功能 | ROI | 决策 |
|---|---|---|---|
| 1 | 本地 LLM 推理 (REQ-LLM-003) | 4.1 | 保留 Pro |
| 2 | PDF 多模态导入 (REQ-MM-001~004) | 4.1 | 保留 Pro |
| 3 | GPU 加速 Metal/CUDA (REQ-LLM-005) | 3.4 | 保留 Pro |
| 4 | 采样参数配置 (REQ-LLM-006) | 3.0 | 保留 Pro |
| 5 | KV Cache 跨会话复用 (REQ-LLM-009) | 3.0 | 保留 Pro |
| 6 | GGUF 模型文件管理 (REQ-LLM-004) | 3.7 | 保留 Pro |
| 7 | VLM 图片理解 (REQ-MM-003) | 3.3 | 保留 Pro |
| 8 | tree-sitter 代码符号 (REQ-RAG-031) | 3.3 | 保留 Pro |
| 9 | 文档一致性审计 (REQ-AUDIT-001~005) | 3.3 | 保留 Pro |
| 10 | 内存层次流式加载 (REQ-LLM-008) | 2.3 | 保留 Pro |
| 11 | 自研 GEMV 内核 (REQ-LLM-007) | 2.0 | 考虑下沉 |
| 12 | ColBERT 多向量嵌入 (REQ-PERF-008) | 2.6 | 考虑下沉 |
| 13 | ONNX 嵌入压缩器 (REQ-PERF-002) | 2.3 | 考虑下沉 |
| 14 | WasmExecutor 代码沙箱 (REQ-RAG-032) | 2.6 | 考虑下沉 |

### 3.3 核心发现

1. **本地 LLM 推理 + PDF 多模态是 Pro 双核心**（ROI 4.1 并列第一），覆盖隐私和文档两大刚需
2. **4 个「考虑下沉」功能均为性能优化型**（GEMV/ColBERT/ONNX 压缩/WasmExecutor），非核心功能，用户感知度低
3. **0 个 Deprecated**：所有 14 个 Pro 功能都有存在价值，无需废弃
4. **维护成本最高的 2 个**：自研 GEMV 内核（6 模块 ~2000 行）+ GPU 加速（Metal/CUDA 跨平台），需持续关注稳定性

## 4. 下沉建议（v3.1+ 候选）

以下 4 个功能建议在 v3.1+ 版本逐步下沉到 Free，扩大用户基数：

| 功能 | 下沉理由 | 预期影响 |
|---|---|---|
| ColBERT 多向量嵌入 | 用户感知度低，Free 单向量已够用 | 提升 Free 版检索质量 |
| ONNX 嵌入压缩器 | Free 版 RuleBasedCompressor 覆盖基本需求 | 提升 Free 版 Prompt 压缩 |
| WasmExecutor 代码沙箱 | 使用场景有限，Agent 模式增强 | 扩大 Free 版 Agent 能力 |
| 自研 GEMV 内核 | 维护成本高，mistral.rs 已含量化 | 减少维护负担（下沉后可简化或废弃） |

**下沉策略**：非一次性全部下沉，而是逐版本评估。每次下沉前需重新评估 ROI 变化。
