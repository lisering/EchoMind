# EchoMind GDPR 合规文档

> **状态**：活跃 | **最后更新**：2026-07-23
>
> 本文档说明 EchoMind 如何符合《通用数据保护条例》（GDPR, General Data Protection Regulation (EU) 2016/679）的要求。

---

## 1. 概述

EchoMind 是一款**本地优先 (Local-First)** 的桌面应用。这一架构选择从根本上简化了 GDPR 合规：

- **数据控制者 (Data Controller)**：用户本人
- **数据处理者 (Data Processor)**：无（EchoMind 不处理任何用户数据）
- **数据存储位置**：用户本地设备
- **数据传输**：仅在用户主动触发时，发送到用户自行配置的 LLM API

**核心结论**：由于 EchoMind 不收集、不存储、不处理任何用户数据（所有数据在用户设备上），EchoMind 团队**不是** GDPR 意义上的数据控制者或数据处理者。

## 2. GDPR 数据处理映射

### 2.1 数据流图

```
用户设备（数据控制者）
  │
  ├── 导入文档 ──→ 本地 SQLite（可选 AES-256 加密）
  │                    ↑ 不离开设备
  │
  ├── RAG 对话 ──→ 检索本地文档片段 ──→ 发送到用户配置的 LLM API
  │                    ↑ 仅片段+问题离开设备          ↑ 用户自行选择的第三方
  │
  ├── OCR（可选）──→ 图片 Base64 ──→ 发送到用户配置的视觉 LLM API
  │                    ↑ 图片离开设备              ↑ 用户自行选择的第三方
  │
  └── 更新检查 ──→ HTTP GET ──→ GitHub API
                       ↑ 无用户数据
```

### 2.2 个人数据处理清单

| 数据类型 | 是否个人数据 | 处理者 | 存储位置 | 传输目标 |
|---|---|---|---|---|
| 导入的文档 | 可能（取决于内容） | 用户 | 本地 | 不传输 |
| 对话历史 | 可能 | 用户 | 本地 | 不传输 |
| 向量嵌入 | 可能（间接） | 用户 | 本地 | 不传输 |
| API Key | 是（凭证） | 用户 | 本地（加密） | 仅认证用，不存储在 EchoMind 服务器 |
| RAG 查询片段 | 可能 | 用户 → LLM 提供商 | 本地 → LLM API | 用户选择的 LLM 提供商 |
| OCR 图片 | 可能 | 用户 → LLM 提供商 | 本地 → LLM API | 用户选择的 LLM 提供商 |
| 崩溃报告 | N/A | — | — | 不收集 |
| 使用统计 | N/A | — | — | 不收集 |

### 2.3 关键合规优势

| GDPR 要求 | EchoMind 做法 | 合规状态 |
|---|---|---|
| 数据最小化（Art. 5） | 仅在本地处理用户主动导入的数据 | ✅ |
| 目的限制（Art. 5） | 数据仅用于用户请求的功能 | ✅ |
| 存储限制（Art. 5） | 数据存储在用户设备，用户随时可删除 | ✅ |
| 完整性和保密性（Art. 5） | SQLCipher AES-256 加密 + 7 层安全防御 | ✅ |
| 问责制（Art. 5） | 审计日志 + 本文档 | ✅ |

## 3. 数据主体权利实现

### 3.1 访问权（Art. 15）

**实现方式**：所有数据存储在用户本地 SQLite 数据库中。

- 用户可通过应用界面查看所有对话、文档和设置
- 用户可通过 `export_diagnostics` IPC 导出系统诊断信息
- 用户可直接使用 `sqlite3` 命令行工具查询数据库（如已解密）

### 3.2 更正权（Art. 16）

**实现方式**：用户可直接在应用中编辑。

- 修改对话标题
- 重新编辑已发送的消息（消息版本管理）
- 重新导入修改后的文档（增量同步）

### 3.3 删除权 / 被遗忘权（Art. 17）

**实现方式**：多级删除机制。

| 删除操作 | 实现 | 安全级别 |
|---|---|---|
| 删除单条文档 | `delete_document` IPC | 普通删除 |
| 安全删除单条文档 | `secure_delete_document` IPC（Crypto Shredding） | 军事级 |
| 删除对话会话 | `delete_session` IPC | 普通删除 |
| 删除所有数据 | 删除数据库文件 + 应用数据目录 | 完全清除 |

### 3.4 限制处理权（Art. 18）

**实现方式**：用户完全控制处理过程。

- 不使用 RAG 对话功能 → 不发送数据到 LLM API
- 不启用 OCR → 不发送图片到 LLM API
- 不启用更新检查 → 不发送请求到 GitHub API
- 启用数据库加密 → 限制数据库访问

### 3.5 数据可携带权（Art. 20）

**实现方式**：多种导出格式。

| 导出类型 | 格式 | IPC 命令 |
|---|---|---|
| 对话导出 | Markdown / JSON / HTML | `export_session` / `export_answer` |
| 知识库包 | ZIP（文档+向量+设置） | `export_kb_package` |
| 配置导出 | JSON | `export_config` |
| 诊断日志 | JSON | `export_diagnostics` |
| 知识图谱 | SVG | 前端导出按钮 |

### 3.6 反对权（Art. 21）

**实现方式**：用户可随时停止使用任何功能。

- 关闭文件监听
- 关闭更新检查
- 关闭 OCR
- 卸载应用

### 3.7 自动化决策拒绝权（Art. 22）

EchoMind 不使用自动化决策或用户画像。AI 回答基于用户明确的查询请求，不进行自动分析或决策。

## 4. 第三方 LLM 提供商的数据处理

当用户使用 RAG 对话或 OCR 功能时，数据会发送到用户自行配置的 LLM API 提供商。在此关系中：

| 角色 | 实体 | 职责 |
|---|---|---|
| 数据控制者 | **用户本人** | 决定将哪些数据发送给 LLM 提供商 |
| 数据处理者 | **LLM 提供商**（如 OpenAI、DeepSeek） | 按其自身隐私政策处理接收到的数据 |
| 软件提供者 | **EchoMind 团队** | 不参与数据处理，不接触用户数据 |

**用户责任**：
- 了解并同意所选择 LLM 提供商的隐私政策
- 评估将文档片段发送给 LLM 提供商的风险
- 对于高度敏感的数据，考虑使用本地 LLM（如 Ollama）

## 5. 数据保护措施

### 5.1 技术措施

| 措施 | 实现 | 对应 GDPR 条款 |
|---|---|---|
| 加密存储 | SQLCipher AES-256-CBC | Art. 32(1)(a) |
| 密钥派生 | Argon2id（64MB/3轮/4并行） | Art. 32(1)(a) |
| 内存擦零 | `zeroize` crate | Art. 32(1)(b) |
| 恒定时间比较 | `subtle` crate | Art. 32(1)(b) |
| PII 检测 | 8 种 PII 类型正则检测 | Art. 25（设计和默认隐私） |
| 审计日志 | 哈希链防篡改日志 | Art. 30（处理活动记录） |
| 安全删除 | Crypto Shredding + VACUUM | Art. 17（删除权） |
| 路径遍历防护 | 所有 Loader 拒绝 `..` 路径 | Art. 32(1)(b) |
| XSS 防护 | DOMPurify 净化所有用户输入 | Art. 32(1)(b) |

### 5.2 组织措施

| 措施 | 实现 |
|---|---|
| 开源审计 | 代码完全公开，可被任何人审查 |
| 供应链安全 | cargo-audit + cargo-deny + Dependabot |
| 安全测试 | SQL 注入/路径遍历/PII 绕过/XSS 测试 |
| 文档化 | 隐私政策 + 服务条款 + 本文档 |

## 6. 数据泄露通知

由于 EchoMind 不存储任何用户数据在 EchoMind 团队的服务器上：

- **EchoMind 团队无法发生数据泄露**（因为我们没有用户数据）
- 如果用户本地设备被入侵，这是用户设备的安全问题，不涉及 EchoMind 团队
- 如果 LLM 提供商发生数据泄露，用户应联系相应的 LLM 提供商

---

## 7. 数据保护影响评估 (DPIA)

EchoMind 的数据处理方式不太可能需要 DPIA（Art. 35），因为：

1. 不大规模处理特殊类别个人数据（Art. 9）
2. 不对个人进行系统性监控
3. 不使用自动化决策或用户画像
4. 数据处理在用户本地设备上进行

但建议用户在以下情况下自行评估：

- 导入大量包含个人身份信息的文档
- 将 RAG 对话用于处理敏感数据（医疗、金融等）
- 启用 OCR 处理包含敏感信息的图片

---

## 8. 儿童数据

EchoMind 不面向 13 岁以下儿童，不收集儿童数据（Art. 8）。

---

## 9. 国际数据传输

### 9.1 EchoMind 团队不进行国际数据传输

EchoMind 团队不收集、不存储、不传输任何用户数据。因此不存在 EchoMind 发起的国际数据传输。

### 9.2 用户发起的数据传输

用户使用 LLM 对话或 OCR 功能时，数据可能传输到用户选择的 LLM 提供商所在的国家/地区。这是用户的个人决定，EchoMind 不参与此过程。

用户应了解：
- 所选 LLM 提供商的数据中心位置
- LLM 提供商的数据处理政策
- 是否适用适当的传输保障措施（SCC、BCR 等）
